# 使用 Azure 每日结果

进入 **SELECTION → 结果来源 → Azure 服务器日报**。首次连接会获取最新发布的结果；以后应用启动、恢复网络，以及北京时间 17:00 之后应用运行期间会检查更新。服务器 17:00 开始运行，发布完成后本机才有新结果。

该模式显示策略选股、每日追踪、B1/B2 持续周期、服务器自选池、完整日报和服务器图表。顶部 RUN 在该模式下也只同步服务器结果。本机自定义选股须显式切换结果来源。断网时已同步结果仍可查看；交易日、修订号和同步状态始终可见。

本机交互 K 线与其他市场工作区仍使用各自本地仓库。服务器结果包目前没有通用指标历史，不能据此宣称本机全市场 K 线已更新。服务器自选快照为只读，不覆盖本机自选。

## 配置

源代码运行时，把 `config/server_results.json.template` 复制到
`data/server_results/connection.json` 并填写现有 SSH 用户、Tailscale 主机及可选密钥路径。
打包运行时，文件位于 `platform_paths.runtime_paths().data_root` 下的同名目录。
连接文件和缓存均不进入 Git 或 App 安装包。目录建议权限 700，连接文件 600。

macOS 优先调用 Tailscale App 自带客户端，避免命令行安装的另一实例处于停止状态。
传输使用系统 OpenSSH、严格主机指纹校验、Tailscale `nc`、固定远端读取命令。
本机浏览器仅请求受 `X-Quant-Session` 保护的本地 API；不接触 SSH 私钥。

当前固定命令以已有授权身份通过 `sudo -n -u quantserver` 执行
`/opt/a-share-quant-server/.venv/bin/python /opt/a-share-quant-server/quant_server/result_reader.py`。
本次线上连接实际由 **Tailscale SSH 身份授权**完成；不能假称仅由指定 PEM 密钥授权。
未修改 tailnet ACL、SSH 配置、sudoers 或账户权限；现有登录身份本身的管理权限没有因此缩小。
未来若部署专用最小权限身份，应同时配置 tailnet 与服务器执行权限并单独验收。

若现有 tailnet 策略要求二次登录，页面会显示“验证 Tailscale 登录”入口；完成后点击同步重试。
这是原有 SSH 身份策略，应用不会自动取消或放宽。验证未完成时保留旧缓存，不自动重算。

## 同步与恢复

- 固定发布身份，校验索引中的 manifest SHA-256、制品长度和 SHA-256、JSON/JSONL 类型、行数、策略/股票关联、数据源及核心质量；校验通过后才替换当前指针。
- 采用应用层 gzip，不依赖 SSH 服务支持压缩。解压大小受 manifest 限制。
- 单文件最多 128 MiB、单包最多 256 MiB、最多 128 个制品、JSONL 最多 200,000 行；页面最多 300 行，默认 100 行。实际首次核验包约 12 MiB。
- 单文件 60 秒无进展或 10 分钟总耗时会中断；取消下载会终止 SSH 进程组，不需要等超时。
- 断线或取消后保留同一发布的暂存文件；重试只复用通过长度和 SHA-256 校验的文件，未完成文件重新下载。不会从不同修订拼装结果。可选文件缺失会在后续同步重试。
- 同包导入幂等，同日修订保留为新版本；历史补发不会把当前日期倒退。自动获取最新可用日期，不把服务器所有历史包一次性镜像到电脑。
- 本机保留最近 20 个已导入版本。损坏/未知协议拒绝激活；可选图表缺失与核心结果失败分开处理。
- 应用关闭或休眠时不承诺后台下载；重新打开或恢复网络后补同步。
