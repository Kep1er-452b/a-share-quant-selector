# Mac 新版迁移与 Windows 桌面启动设计

## 目标

将 `C:\Users\13200\Downloads\a-share-quant-selector.zip` 中的新版 macOS
量化系统迁移到当前 Windows 工程，并交付一个桌面快捷方式。用户双击快捷方式后，
系统应直接打开独立的量化系统窗口，不需要输入命令，也不应出现常驻的命令行窗口。

## 范围和保护边界

- 源码以压缩包内的 `a-share-quant-selector/` 为准；迁移前在隔离目录解压和比对，
  不直接覆盖当前工程。
- 迁移功能代码、测试、前端资源和必要的静态资源；忽略 macOS 元数据、macOS 虚拟环境、
  Git 元数据、构建产物、缓存和临时文件。
- 保留 Windows 本地运行状态：`data/`、本地配置文件、凭据、日志、现有 Windows
  虚拟环境和用户已有的未提交工作。
- macOS 专用的 `.app` 构建脚本、shell 启动脚本、Unix 路径与权限假设不直接带入。
  对应功能采用 Windows 启动器和 PowerShell/快捷方式实现。

## 迁移流程

1. 将压缩包解压到工程外的临时迁移目录，排除 `__MACOSX/` 和无关运行目录。
2. 将新版源码与当前 Windows 工程比较，按文件合并新版功能；若发生平台冲突，保留
   Windows 兼容逻辑并将新的跨平台行为接入其中。
3. 对启动路径、Python 解释器位置、日志目录、浏览器代理绕过、编码和图标等平台差异
   做 Windows 适配。
4. 为桌面启动器提供稳定入口。快捷方式调用项目虚拟环境的 `pythonw.exe` 与
   `launch_desktop_app.py`，因此启动时不显示命令窗口；启动器继续使用 pywebview
   承载本地 Flask 界面。
5. 在当前用户桌面创建“`A股量化选股系统`”快捷方式，设置工作目录、图标和启动参数。
   若启动前检查失败，应用窗口应显示中文错误信息，并把诊断写到运行日志目录。

## 组件与数据流

`桌面快捷方式` → `pythonw.exe` → `launch_desktop_app.py` → 本地 Flask 后端 →
`pywebview` 应用窗口。

启动器以项目目录为工作目录，选择 Windows 虚拟环境下的解释器，绕过系统代理访问
`localhost`，等待健康检查成功后将窗口加载到实际本地端口。后端不成功时，启动器不应
执行数据更新、选股或通知，只显示失败页面并保留日志线索。

## 验证标准

- 新版合并后的 Python 文件通过编译检查，前端 JavaScript 通过语法检查。
- 与迁移文件相关的 pytest 用例通过；风险允许时运行完整测试套件。
- 启动器的环境检查、pywebview 可用性检查和无 GUI 后端烟雾检查通过。
- 通过 Windows Shell 验证快捷方式目标、工作目录与图标设置，并实际启动确认窗口可打开。
- 不执行全市场数据更新、不发送钉钉通知，也不修改现有股票数据。

## 非目标

- 本次不打包单文件 `.exe`，不改变量化策略规则，也不迁移 macOS 的 `.app` 包。
- 本次不覆盖或清理用户本地数据、Token、日志或未提交改动。
