## 启动与日常更新

从本仓库启动新代码：

```bash
.venv/bin/python main.py doctor
.venv/bin/python main.py web --host 127.0.0.1 --port 5080
```

已有 Web 进程需重启，随后刷新页面。从仓库运行 `launch_desktop_app.py` 也可使用新功能；已有独立打包应用包含的是其打包时的代码，需要另行重打包后才包含本次变更。

日常更新在 UPDATE 中选择 Tushare，并勾选“按交易日批量获取核心行情”。这次选择只作用于该任务。CLI 使用本地配置中的开关：

```yaml
data_source:
  tushare:
    batch_daily_enabled: true
```

将这一小段合入被 Git 忽略的 `config/config_local.yaml`，不要覆盖已有 Token 和其他配置。模板默认仍为 false，保留逐次启用和观察的阶段。关闭复选框或将该值改为 false 可恢复原更新路径。建议在至少三个正常交易日确认价格、命中、缺漏和端到端耗时后再把新路径设为长期默认。

核心流程按日期准备三种数据，再分组成股票 CSV 增量。分页达到上限会继续请求；空首批、重复页、配套因子或指标缺失都会报错，不能视为整日完成。停牌或缺证券日期会转到逐股权威路径验证。最新两个日期重新读取以接收源数据修订；更早的已验证切片可以复用。

`data/providers/tushare/batch/state.json` 在请求前保存具体切片、目标股票及每只股票范围、SDK/价格适配上下文，记录 failed/cancelled/prepared/resumed 状态。prepared 仅表示输入准备完成，CSV 写入与任务成功仍由原同步汇总判定。相同证券集合和环境重试会包含旧未完成切片，即使新计算的窗口已前移；改变集合不会删除旧计划。SDK/价格适配变化会拒绝跳过未完成计划。旧缺口与新增日期合计超过 40 日时，需先关闭批量模式，通过原路径补历史，再重新启用。

前复权使用“原始价格 × 当日因子 / 可见范围最新因子”，价格按本环境 Tushare `pro_bar` 的两位小数格式。CSV 的元市值、供应商成交量单位、倒序、锁和原子写入继续生效。锚点变化仍触发原有受控全量修复，不将价格重复复权。

任务的 `core_timings`/`core_elapsed_seconds` 计量核心同步，不包含全部市场缓存、扩展数据与任务前置检查。查看完整更新状态和日志才能判断端到端耗时；附加阶段失败与核心数据是否完成是不同事实。

## 公式、快照与研究池

1. 进入 A 股 → RESEARCH。输入公式名称、白名单条件和参数定义，保存一个版本。例如 `C > MA(C, N)`，N 的默认值 20、范围 2～250。
2. 输入逗号分隔的证券冻结小集合；留空会冻结当前仓库，最多 6,000 只。冻结的是实际分析 frame，包括读取错误记录，不是可变 CSV 的路径引用。
3. 选择快照、公式及版本，先做单股测试，再执行研究运行。普通 CLI/Web A 股选股也会保存 run_id、snapshot_id。
4. “运行公式版本”可指定旧版本。保存修改会产生新版本，归档不会删除旧证据。公式仍通过现有白名单解析器执行，不能执行任意 Python。
5. 创建四类研究池或自定义池；一只证券可以存在于多个池。迁入原自选只读原文件，保存独立版本并保留顺序。历史会话内新建的池有独立 session_id；全局池仍作为当前个人研究工具。

运行保存策略 YAML、解析后的公式和参数、输入 hash、结果及实际执行源码，记录 Python/依赖/C 核心指纹。打包环境缺少 C 源码时显式记录 `executor_source_missing`。历史结果可直接读取；重算仍使用当前执行器，跨代码版本复现需要核对保存的执行器指纹并恢复对应代码环境，不会自动执行档案内任意源码。失败、取消、partial 不替换 last_run；写入失败事务回滚。

图表先加载价格，再补指标，指标计算使用完整可见历史暖机后截取窗口。原始因子档案显示前复权价格及其锚点，模拟成交详情保留原始价格。范围统计覆盖所选区间，绘制最多 2,000 根；成交量明确标注股、手或供应商原单位。快速切换和离开页面会取消过期请求并释放图表。港股上下文显示尚未支持，不能使用 A 股回放/账户规则。

## 历史档案与时点边界

通过“导入原始行情档案”提交 JSON。单档案最多 100 只证券、合计 100,000 行、单证券 10,000 行，HTTP 请求最多 10 MiB。档案明确来源与修订，原始 OHLC、成交量/额和 adj_factor 必须有效；日期唯一且处于已提供的上市区间。以下为结构示例，价格为虚构数据：

```json
{
  "market": "a_share",
  "price_view": "raw_with_factors",
  "source": "示例；请替换为真实来源",
  "source_revision": "2026-10-02",
  "historical_universe": true,
  "daily_metrics_point_in_time": true,
  "instruments": [{
    "symbol": "000001.SZ",
    "name": "示例证券",
    "list_date": "2020-01-01",
    "name_history": [{"from": "2020-01-01", "name": "示例证券", "known_from": "2020-01-01"}],
    "volume_unit": "shares",
    "corporate_actions": [],
    "bars": [{"date": "2026-09-30", "open": 10, "high": 11, "low": 9,
      "close": 10.1, "volume": 100000, "amount": 1000000, "adj_factor": 1,
      "market_cap": 1000000000, "turnover": 1, "up_limit": 11, "down_limit": 9}]
  }]
}
```

`historical_universe` 和 `daily_metrics_point_in_time` 是供应档案者的证据声明，必须为 JSON 布尔值。系统检查结构与字段，无法仅由此证实历史集合没有遗漏退市股或数据没有事后修订。声明当日指标可用于时点研究时，必须提供各日正市值与换手率。区间外上市/退市、历史 ST/名称记录参与筛选；缺少相应证据时不放行相关条件。财务公告及首次可见时间尚未接入，不能做财务条件的严格时点回测。

普通当前 CSV 可做价格复盘，限制到 OHLCV/技术指标公式，禁用历史市值和当前名称筛选，并显式记录生存者偏差和当前复权锚点的限制。开盘前 reader 排除当天完整 bar；收盘后包含当天。基于原始因子的档案按可见截止日重新确定复权锚点，未来极端价格或未来因子不影响过去信号。

会话推进顺序为“收盘后 → 下一档案交易日开盘前 → 当日收盘后”。检查点事务保存会话、上一次运行的公式配置、会话池和账户版本；尚未执行的页面参数编辑不算入会话配置。恢复创建分支，保留原会话及后续记录。会话中的选股任务冻结提交时点，时点推进或切换会请求取消旧研究任务；旧完成响应不能自动替换新上下文。

## 模拟账户规则

规则版本为 `a_share_daily_open_v1_20261002`，接受 2023-08-28 之后的日期。使用导入档案的原始价格和明确涨跌停价格；不直接拿复权价格计算现金。只做现金账户普通买卖。

- 收盘后的信号/订单最早下一档案交易日开盘成交，开盘提交也从下一日开始；T+1、预留资金与待卖订单数量检查生效。
- 主板/创业板买入以 100 股为单位；科创板至少 200 股、其后 1 股；北交所至少 100 股、其后 1 股；全部卖出允许余下零股。
- 成交容量为前一个可见日成交量的一定比例，股/手显式换算。容量不足允许部分成交；订单有效至撤销。没有当日 bar 视为停牌/无数据而等待。
- 涨停开盘不买、跌停开盘不卖；滑点越过明确涨跌停价不成交。日线没有盘口，不能据此证明真实开盘可成交。
- 默认佣金万三、单订单最低 5 元；过户费万分之 0.1 双边、卖出印花税万分之 5、滑点 5 bps、容量 1%。这些是创建账户时可调整、保存后固定的模拟假设，不能替代具体券商收费核对。金额使用十进制运算、分币四舍五入；多次部分成交累计最低佣金。
- 公司行动需要 record_date/ex_date；现金分红采用明确的 `cash_per_share_net` 与 pay_date；送转采用 bonus_ratio 与 delivery_date。根据登记日真实持仓建立应收和到账/交付事件，不自行推测红利税、配股或复杂重组。缺少解释因子变化的公司行动、到期行动未入账、退市结算或估值缺证据时暂停净值发布。
- 报告保留持仓、现金、可用资金、分项费用、应收、成交事件中的 realized_pnl、净值与回撤。每次修改和读报告都核对现金、数量、成本基础与事件账本恒等式。

核验依据：[Tushare 日线及行数上限](https://tushare.pro/document/1?doc_id=27)、[上交所 2026 交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[深交所 2026 规则通知](https://investor.szse.cn/lawrules/rule/trade/t20260424_620190.html)、[北交所交易规则](https://www.bse.cn/jygl_list/200028217.html)、[税务部门印花税口径](https://shanghai.chinatax.gov.cn/zcfw/rdwd/202309/t468612.html)。首次规则核验与软件单元测试不等于历史所有制度变化的独立审计。

## 存储、备份与回退

批量缓存是供应商原始切片，研究库是独立 `data/research/research.sqlite`，Tushare 扩展库及各领域库继续独立。研究库以 gzip 压缩、内容 hash 去重保存实际 frame；相同 frame 可复用，数据变化会保留新版本，因此大量全市场冻结会增加磁盘占用。原始切片不自动删除，计划账本只收敛已完成规划记录；需要清理时应先核对引用、备份和保留策略。

启动新代码按需创建 schema v1，新库不会迁移覆盖 CSV、扩展 SQLite 或自选文件。运行数据保持 Git 忽略和代码资源打包规则。

更新回退先取消并等待后台任务结束，关闭批量开关；停止冲突写入后，对受影响 CSV、batch 状态、研究 SQLite 和本地配置做一致备份。SQLite 使用其 backup API 或在所有写者停止后复制数据库及必要 WAL；不能在线只拷贝 `.sqlite` 主文件。代码和数据应回到匹配的已验证版本。保留失败记录和原计划，不通过删除证据显示成功；不要用 `git reset --hard` 丢弃本仓库原有未提交工作。
