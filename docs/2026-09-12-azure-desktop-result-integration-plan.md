## 2. 已核验事实及缺口

1. 服务器 `quant_server/result_contract.py` 已实现 `capabilities`、`list_releases`、`get_manifest`、`fetch_artifact`；它们是 Python 文件访问接口，不是已监听的网络 API。
2. `quant_server/result_export.py` 已发布不可变目录、manifest、SHA-256 和索引；数据根目录通过 `ServerPaths.exports_root` 映射至 `exports/`。已提交配置启用导出，保留期设为 365 天；线上配置待查。
3. 已有筛选明细、逐策略评估状态、每日追踪、持续选股周期、自选快照、市场摘要、完整日报、分段日报及图表。选股项 `trigger` 保存原始选股结果对象，包含信号的可能性已由写入代码确认，实际发布字段仍需样例验收。
4. `indicator-values.jsonl` 当前固定为空；coverage 明确报告 `not_computed`，原因是消费者字段尚未协商。不能把它当作完整指标仓库。
5. 本机 `renderSelectionResults()` 需要按策略分组的 `code/name/signals`，信号使用 close、J、market_cap、reasons 及策略特有指标。现有选股入口启动本地异步计算，缺少服务器结果消费者。
6. 服务器 `quant-daily.timer` 配置工作日北京时间 17:00 启动。结果导出位于 `daily_finalize.py`，会受追踪批次和最终整理流程影响；飞书投递状态与结果发布状态不能混为一谈。
7. 本机 Tailscale CLI 本次返回 `BackendState=Stopped`、无 peers。这只证明本次 CLI 观察到的状态，不能排除其他客户端实例或随后恢复连接。找到 SSH 密钥文件，仅确认路径，未读取私钥正文；本次未建立 SSH 连接。

## 3. 推荐通信方案

首版采用 **Tailscale 内网 + SSH/SFTP 只读拉取不可变结果包**。复用现有文件协议和 SSH，服务器无需增加 Flask 或公网 HTTP 服务。

数据流：服务器定时计算 → 原子发布 `exports/releases/<release_id>` → 更新 `index.json` → 本机后台同步 → 暂存与校验 → 原子激活本地版本 → 现有页面展示。

- 首先核验 Tailscale 在线节点、目标主机身份、已知 SSH 主机指纹及真实部署路径。不通过关闭主机身份检查解决连接问题。
- 日常消费者使用受限只读 SSH/SFTP 身份，只允许读取导出目录；现有管理密钥可用于经授权的部署核验，长期运行不依赖管理员权限。具体权限和 SFTP 目录配置在服务器实勘后落定。
- 凭据与连接地址放在本机忽略的配置或系统凭据存储；浏览器只调用本机受会话保护的 API，不接触私钥。打包产物不携带凭据或结果包。
- 同步不从本机触发远端每日重跑，不抓取远端运行 SQLite，不覆盖本机 CSV 仓库。
- 标准 SSH 密钥认证与 Tailscale SSH 是不同机制；首版不假设已经启用 Tailscale SSH。

## 4. 首版范围与页面字段映射

| 本机呈现 | 服务器来源 | 接入规则 |
| --- | --- | --- |
| 按策略选股、代码、名称 | selection-items | 按 strategy_id 分组，保留完整策略身份；空策略依据 coverage 显示 |
| 收盘价、J、市值、触发原因 | selection-items.trigger 的原始 signals | 明确映射；缺失显示 `--` 与原因，不调用本地指标补算 |
| 策略错误、跳过、未命中 | evaluation-status + coverage | 分别统计；零命中不等于计算失败或未计算 |
| 昨日选股/长期自选每日表现 | tracking-daily | 显示官方涨跌、量能、单位、有效性和所属来源 |
| B1/B2 持续周期 | selection-tracking | 保留入场信息、升级历史、当前状态、停止原因 |
| 市场摘要 | market-summary | 仅映射实际已提供字段，不假设覆盖本机全部热力图/Market Pulse |
| 日报与图表 | daily-report、report-parts、charts | 经校验的本地缓存读取；Markdown 安全渲染，禁任意本地路径访问 |
| 服务器自选池 | watchlist-snapshot | 只读独立展示，不覆盖本机自选池 |

首版交付以“直接使用服务器完整日报、选股和追踪结果”为验收范围，日常复盘无需本地全市场更新或选股。本机切换到服务器结果模式后，默认展示最新已验证发布，手动操作名为“同步服务器结果”；本地自定义选股保留为明确的独立入口。

结果数据源独立于行情 provider：不把 server 加进 Tushare/AkShare/Tencent 仓库切换逻辑。服务器结果限定 A 股，香港及其他工作区保持原有边界。服务器策略参数与本机参数不一致时展示服务器配置摘要/指纹，本机控件不能把服务器结果重新标记成本地配置计算结果。

**K 线边界：** 当前结果包不含完整交互 K 线历史或全部图表指标。第一阶段提供服务器生成的图表；打开已有本机 K 线时明确显示本机行情截止日期，不能声称它已同步。若要求所有交互 K 线同样无需本机更新，第二阶段增加所需股票的有界行情及已计算指标制品，由服务器在计算流程中保存并导出。本机仅绘图；全市场历史、宏观/期货等仓库镜像不属于首版。

## 5. 协议与一致性

复用服务器 `contracts/daily-result/v1/`，补充数据集结构、脱敏真实样例及两端兼容测试。已有 `schema_version=1.0.0` 是结果协议，不另设项目版本。协议升级先明确兼容规则；不能任意接受未知版本。

校验顺序：索引 → 固定 release_id → manifest 及索引中的 manifest 哈希 → 必需制品大小/哈希 → JSON 类型、有限数值、日期和行数 → 唯一键及关联关系 → 质量判定 → 原子激活。

- 对路径穿越、符号链接越界、非预期制品、过大文件和行数设置明确限制，限制值依据实际包尺寸制定。
- 显式验证 A 股/Tushare 来源、交易日期、策略身份、股票代码、单位、复权口径和 producer 信息。百分数 3.2 表示 3.2%，量为手、金额为元。
- 对 selection-items 使用 `(code, strategy_id)` 唯一键；追踪周期按其真实 interval 身份，不把同股多周期误判重复。
- 同日修订是新发布，保留原 release。发布序号用于发现更新；“当前展示日期”不因较晚发布的历史补算退回过去。游标在激活成功后推进。
- 重复包幂等；损坏或断网保留上一有效版本；过期包显示 `artifact_expired` 并重新发现可用发布，不循环下载或跳过后假称成功。
- 区分核心失败、可用但有警告、缺少可选图表、飞书尚未投递。失败包可保留诊断，不能冒充正常完成；实际允许状态表以服务器代码和样例为准。
- 索引发生回退、重建或 publication_seq 冲突时重新核对 release_id 和历史指纹，不能仅依赖一个递增数值。

## 6. 本机运行与暂停恢复

应用打开时立即检查索引；交易日 17:00 后在应用运行期间以有界退避轮询，发布完成即拉取。时间判断采用 Asia/Shanghai 与交易日历；节假日不能按周一至周五直接认定应有新包。服务器未提供可靠任务状态时，界面写“尚未发布今日结果”，不推断“正在计算”。

应用关闭或电脑休眠时首版不要求后台守护，重新打开、唤醒或恢复网络后补同步。若未来需要应用关闭时也下载，再增加独立本机调度；本次不创建自动任务。

状态包括：未配置、连接失败、等待发布、下载中、校验中、可用、可用但有警告、旧缓存。显示结果交易日、发布时间、来源、上次同步时间和错误原因。

同步使用现有后台任务/取消/轮询模式，设连接和读超时、单实例互斥、文件级取消点。取消只删除或保留暂存状态，不破坏当前缓存；大文件续传仅在传输适配器经验证支持时启用，否则按文件重新下载。

协作暂停约定：用户说“停”即停止发起新操作，尽快取消正在运行的可中断操作，留下两项目状态、当前步骤和待验证事项；收到“继续”先复核网络及工作区再恢复。长远程操作使用短超时或可追踪会话，避免不可中断等待。

## 8. 必须通过的验收

1. 真实交易日发布的 release_id、日期、策略信号数、逐股数据与本机显示一致，抽查日报和图表哈希。
2. 本机查看/同步服务器结果期间，本地 selection worker、Tushare 全市场更新和隐式指标补算调用次数为零。
3. 17:00 尚未发布、节假日、离线、休眠后恢复均显示正确状态，旧数据不标成今日完成。
4. 断网、取消、重启、损坏制品、未知协议、路径越界、过期包均不损坏上一有效缓存。
5. 同包重复导入幂等；同日新修订可切换；迟到的历史发布不会替换较新交易日。
6. 零信号、部分策略失败、未计算指标与缺失图表呈现可区分；本机自选及原行情数据未被覆盖。
7. 两端聚焦契约/同步测试通过；业务代码变更后各自运行适当回归。显著前端变更需真实本机 Web/桌面交互检查，并验证香港上下文隔离与页面切换取消。
8. 线上首个自然定时发布完成后再确认自动获取闭环；手动抓取历史包仅证明传输链路，不能替代自然发布验收。
